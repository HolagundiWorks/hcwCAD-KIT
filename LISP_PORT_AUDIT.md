# HCW AutoCAD Plugin — LISP Port Audit

The original `HCW-ALL.lsp` is not present in this repository, so this audits the ported C# code itself (against the README's description of intended behavior) rather than diffing against the LISP source.

## 1. Merge candidates

- **Room-type array quintuplicated.** The identical 29-entry room-type `string[]` (Bedroom…Gym) is hardcoded in `Commands/RoomCommandsMetric.cs:110`, `Commands/RoomCommandsFeet.cs:110`, `Commands/RoomCommandsInches.cs:110`, and again in `Commands/RoomCommandsUnified.cs:18-24`, in an order that doesn't even match the canonical list in `LayerData.cs:233-264` (`LayerData.RoomTypes`, which already has codes+labels). A drawing-list of 29 rooms is duplicated 4x plus a 5th canonical copy that isn't reused. Fix: have all four command classes build the array from `LayerData.RoomTypes.Select(r => r.RoomType).ToArray()` once.
- **Per-unit "create N per-type commands" boilerplate.** `RoomCommandsMetric.cs`, `RoomCommandsFeet.cs`, `RoomCommandsInches.cs` are 29 near-identical `[CommandMethod] void MXX() => Engine.CreateLabel(...)` one-liners each (lines 11-96 in each file), differing only by command-name prefix and `Engine` field — this is inherent to needing distinct AutoCAD command names per unit system, so it's a reasonable candidate for a Roslyn/T4 source generator (the README already calls these files "(generated)") rather than hand duplication, but as hand-written code it's ~90 lines of copy-paste per file.
- **MHELP/FHELP/IHELP text blocks** (`RoomCommandsMetric.cs:158-174`, `RoomCommandsFeet.cs:158-174`, `RoomCommandsInches.cs:158-174`) are line-for-line identical except for the prefix letter and unit name — could be a single shared `RoomEngine.PrintHelp(Editor ed)` method parameterized by `SystemTag`, eliminating ~45 duplicated lines.
- **"create/verify all layers from a data table" loop** is duplicated 3x with the same shape: `BpltCommands.CreateAllLayers` (`BpltCommands.cs:19-26`), `HcwLayerCommands.HcwLayers` (`HcwLayerCommands.cs:24-36`), `VhLayerCommands.VhLayers` (`VhLayerCommands.cs:16-32`), and again inline in `MeasureCommands.MakeLayers` (`MeasureCommands.cs:44-58`). All four do `foreach (var ld in LayerData.X) Util.EnsureLayer(tr, db, ld.Name, ...)`. A single generic `Util.EnsureLayers(tr, db, IEnumerable<T> data, Func<T,...>)` helper would remove ~4 duplicated loop shapes.
- **RoomCommandsUnified.cs** (lines 26-98) is itself a full duplicate wrapper of every RoomEngine method already exposed 3x via Metric/Feet/Inches command classes, just redirecting through `RoomUnitSelector.Current` — functionally justified per the README (single ribbon panel) but worth flagging since it's a 4th near-identical command surface over the same `RoomEngine` API.

## 2. Removal candidates

- **`RoomEngine.ToDisplayLength(double raw)`** (`RoomEngine.cs:65`, implemented per subclass) is declared and overridden three times, but never called anywhere in the codebase (confirmed via project-wide search — only its own declarations/definitions match). Dead API surface ported presumably for a use that never materialized. Fix: delete the abstract member and its overrides, or wire it into `AreaLabelForSelected`/`FormatDim` if it was meant to be used there.
- **`Commands/RoomCommandsUnified.cs`'s local `RoomTypes` array** (lines 18-24) is redundant with `LayerData.RoomTypes` — see merge candidate above; once merged, this local copy should be deleted rather than merely deduplicated.
- No fully dead commands or no-op commands were found otherwise — every `[CommandMethod]` reachable from the ribbon/README table has a body that does real work.

## 3. Correctness / logic concerns

- **`RoomEngineInches.DefaultTextHeight = 0.15`** (`RoomEngine.cs`) is almost certainly a copy-paste leftover from `RoomEngineMetric.DefaultTextHeight = 0.15` (metres) and was never rescaled for the Inches system. `RoomEngineFeet.DefaultTextHeight = 0.5` (feet) is the correctly-scaled sibling — its inch equivalent should be ~6 (0.5 ft × 12), not 0.15. As written, `IROOM`/`IBR`/etc. draw room-type/dimension/area text at 0.15 *inches* tall by default (roughly the size of a printed period), illegible in an inches-based drawing. **Status: fixed in this session** — the new unit-aware engine derives default text height from a real-world mm target instead of a hardcoded per-system guess.
- **`Commands/TextToolCommands.cs` `WinLabel()`** (lines 174-219): `Util.EnsureLayer(tr, db, "WIN_LABELS", 7)` runs first inside the transaction, but if the subsequent selection prompt or point prompt fails, the method returns without calling `tr.Commit()`. Because the `using (var tr = ...)` block rolls back on dispose without a commit, the just-created `WIN_LABELS` layer is silently discarded even though no error was reported. Low-impact (recreated on next successful run) but inconsistent with the rest of the codebase's commit-before-early-return pattern. Fix: move `EnsureLayer` after both prompts succeed, or commit before the early returns.
- **`DeleteAreaTextCommands.AreaPattern`** (`DeleteAreaTextCommands.cs:17`, `^AREA:\s*\S`) is looser than its own doc comment claims ("Area: <number>[unit]") — it matches *any* text beginning "Area:" followed by non-whitespace, including non-numeric content (e.g. a manually-typed "Area: TBD" note). Since this command bulk-deletes matching TEXT/MTEXT across the whole drawing by default (`[All/Selection] <All>`), a user-authored note starting with "Area:" would be silently erased. Fix: tighten the regex to require a numeric value, e.g. `^AREA:\s*[\d.]`.
- **Systemic gap (root cause of the reported "Feet is 12x off" bug): none of the three Room Dimension engines verified the drawing's actual `Database.Insunits` against their own hardcoded unit assumption.** `RoomEngineFeet` assumed "1 drawing unit = 1 foot" unconditionally; if the drawing was actually set up in inches (common), every Feet-system dimension/area was inflated 12x. `RoomEngineMetric`/`RoomEngineFeet`/`RoomEngineInches` were each internally self-consistent, but none cross-checked against the drawing. **Status: fixed in this session** — `RoomEngineFeet` now checks `Insunits` and divides by 12 when the drawing is actually in inches, and a new `RoomEngineAuto` engine (used by the unified `HCWROOM*` ribbon commands) reads `Insunits` directly and scales for mm/cm/m/ft/in automatically, removing the need to pick a system by hand.

## 4. Optimization opportunities

- **`BpltCommands.BpltCheck`** (`BpltCommands.cs:111-142`) is O(required-layers × entities-in-space): for each of the ~21 `AP-*` layers it re-scans every entity in `CurrentSpaceId`. For a drawing with thousands of entities this becomes tens of thousands of `GetObject` calls. Fix: single pass over `btr` building a `Dictionary<string,bool>` (layer → has-closed-polyline), then report against `required` — same pattern already used correctly in `BpltAreaCommands.BpltArea` and `HcwLayerCommands.HcwSchedule`.
- **Repeated `LayerTable`/`LinetypeTable` re-fetch inside `Util.EnsureLayer`/`Util.LoadLinetype`**: every call does its own `tr.GetObject(...)`. Because `CreateAllLayers`/`HcwLayers`/`VhLayers`/`MeasureCommands.MakeLayers` call `EnsureLayer` in a loop (92, 36, 75, and 12 times respectively), the same tables get round-tripped from the transaction dozens of times per command. Caching the table reference once per loop would remove the repeated lookup. Low severity given typical layer counts, but easy to fix.
- **`MeasureCommands.MakeLayers`** is called unconditionally at the top of every `MSETUP`/`MLIN`/`MBRK`/`MBML`/`MREC`/`MARE`/`MSLB` invocation, re-verifying all 12 MEASURE layers every single call even mid-session when they're already guaranteed to exist. Not incorrect (idempotent), but needless repeated work on the hottest path in the toolkit. Fix: track a per-document "layers ensured" flag, or only call it from `MSETUP`.
- No other significant inefficiencies were found — most audit/report/schedule commands (`HCWSCHEDULE`, `HCWAUDIT2`, `BPLTAREA`, `TXTAUDIT`, `TXTEXPORT`) already do a correct single pass over entities.
